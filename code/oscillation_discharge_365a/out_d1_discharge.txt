§4  WHAT CARRIES THE FINDING: OWED AGAINST PAID  (P5)
--------------------------------------------------------------------------------------------
  `./build.sh` regenerates transcripts into the worktree and THEN g0 compares the
  worktree against HEAD.  So the old §2's disagreement set D(T) CONTAINS every
  watched transcript the landing went on to commit: a landing that committed one
  PROVABLY had D(T) != {}, would have carried a RED §2, and would have owed a
  refresh.  Transcripts graded NOISE or CORPUS are restored rather than committed,
  so they never appear here — this is a LOWER BOUND, which is the safe direction
  for a claim that the toll was owed and not paid.

  The watched class is `lib_f771.is_watched`, IMPORTED.  The corpus-scoped registry
  is `lib_f771.CORPUS_SCOPED`, imported for the same reason: a hand-typed glob or a
  hard-coded exemption path is a re-statement, and a re-statement drifts.

§6  THE SELF-INCLUSION QUESTION, ANSWERED BY MEASUREMENT  (P8)
--------------------------------------------------------------------------------------------
  Question 1 asks whether a self-inclusive count is a defect or the only truthful
  arrangement.  It was NEITHER: it was a property of the exemption, and it is gone.

  The counting directory joined the population it counted because COUNTING
  REQUIRED A ./build.sh RUN AND A ./build.sh RUN MOVED THAT TRANSCRIPT.  Nothing
  about counting made the count self-inclusive; the oscillation did, and it
  captured every branch equally — mg-585e was not special, it was the 9th.

  With the exemption deleted the transcript is a function of lib_f771.py's source,
  so a landing that does not touch that file does not move it.  A directory can
  now count the population without entering it.

  so it is ON STDERR and not here (README D4).  A branch-dependent reading in a
  pinned transcript is the defect this whole arc is about, arriving one file over.
