-- (iii) OPTIONS.  Population: the option list of `man git-log`.
         Grain: one option.

      --abbrev-commit      Instead of showing the full 40-byte hexadecimal commit object name, show a prefi
      --no-abbrev-commit   Show the full 40-byte hexadecimal commit object name. This negates --abbrev-comm
      --oneline            This is a shorthand for --pretty=oneline --abbrev-commit used together.

   `--oneline` is `--pretty=oneline --abbrev-commit` by git's own
   words, so it is a spelling of a hash and this instrument counts it.
   `--abbrev-commit` does not by itself make a hash appear -- it
   changes the GRAIN of one that already does -- so it demotes FULL
   to ABBREV within the same call and is never an emitter alone.

-- (iv) THE DEFAULT.  A `git log` with NO format argument.

      =<format> part is omitted, it defaults to medium.
      (i.e.  medium, which is the default, full, and fuller).
      Default for the --format option. (See Pretty Formats above.) Defaults to medium.

   git's documented default is `medium`, whose sample is
   `commit <hash>`.  So a bare `git log ... ` PRINTS A FULL COMMIT
   HASH AND IS REVISION-PRODUCING, and mg-330a's classifier returns
   None for it.  This instrument keeps that call OUT of its headline
   denominator (POP-C) and measures it separately as POP-D, because
   whether an unformatted `git log` is an ANCHOR is a judgement and
   not a reading -- so it is published as its own number rather than
   folded into somebody else's.

-- (v) WHAT IS OUTSIDE THIS POPULATION, NAMED RATHER THAN DROPPED

   The population above is `git log` calls.  These also address a
   commit and are NOT counted anywhere in this instrument, because
   mg-330a's taxonomy is about `git log` and changing the subcommand
   set would make the before/after incomparable:
      git rev-parse --short <rev>      an abbreviated object name
      git rev-parse <rev>              a full object name
      git show -s --format=%H          the same placeholders, elsewhere
      git describe                     a name relative to a tag
      git rev-list                     the same placeholders again
      git for-each-ref --format=%(objectname)
   Each is a real way to address a commit.  Naming them is what this
   ticket does; absorbing them into a count whose label says `git log`
   would be the same defect with the sign flipped.
