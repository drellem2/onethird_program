----------------------------------------------------------------------------------------------------
PART A -- val(C) <= val(tc(C)) : the maximum sits on a transitively closed branch
----------------------------------------------------------------------------------------------------

  Why it is true (the document has the proof): the columns of C and of tc(C) are
  the SAME set -- a permutation respecting C respects tc(C) -- while a pair in
  tc(C)\C is called incomparable by C and therefore carries per-slot rows
  J_k(i,j) = J_k(j,i); no column flips it, so J_k(j,i) = 0 and the row reads
  J_k(i,j) = 0, a constraint tc(C) does not impose.  So feasible(C) is contained
  in feasible(tc(C)) and the value can only rise.  Checked:

  n=4 (ALL 64 branches):  64 branches, 0 violations of val(C) <= val(tc(C))
        max over all tested = 1;  max over transitively closed = 1;  ATTAINED ON A CLOSED BRANCH
  n=5 (ALL 1024 branches):  1024 branches, 0 violations of val(C) <= val(tc(C))
        max over all tested = 4/3;  max over transitively closed = 4/3;  ATTAINED ON A CLOSED BRANCH
