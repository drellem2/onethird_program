# `code/verdict_staleness_30bd/` — the second class of staleness, and nobody was counting it

`code/asof_census_20ee` measures **stale addresses**: a `path:NNN` printed into a file the
instrument does not own, which moves when somebody else edits that file. mg-20ee's own words
about that population are

> the verdicts are not affected … this must not be reported as a correctness defect

and that sentence is **true of the population that census measures and false of the corpus**.
A transcript can drift in its **verdicts** with no address moving at all, and such a
transcript is invisible to an address classifier *by construction* — it is not looking for
that.

`code/species_extent_audit_6cb9` is the existence proof. Its committed `out_a1_bothways.txt`
says `A1 TOTAL BAD: 1` with a `*** MISSED ***` row and two `*** EXTENT WIDER ***` rows; the
same script at HEAD today says `A1 TOTAL BAD: 0` and those rows are gone. **6cb9 is not among
mg-20ee's 44 candidates**, so it sits outside the corrected population of 32 entirely. It was
found **by accident**, by `p6e4f`, while pinning something else.

A stale address relocates a reader wrongly. **A stale verdict says the corpus measured
something it no longer measures — and it reads as a finding.**

**This directory measures that population. It repairs nothing.** A verdict that has moved is a
finding about the corpus and needs an owner per instance, not a batch repair.

| file | what it is |
|---|---|
| `lib30bd.py` | the classifier, and §2's token set — **the instrument** |
| `selftest_30bd.py` / `out_selftest_30bd.txt` | 19 planted worlds. **Five must come out BENIGN** |
| `sweep.py` / `sweep_30bd.jsonl` / `out_sweep_30bd.txt` | the measurement. Hours; **not** a fixed point, **not** in `run_all.sh` |
| `report.py` / `out_verdict_staleness.txt` | the count. A pure function of the frozen record |
| `prose_30bd.py` / `out_prose_30bd.txt` | mg-2959: **the same question asked of this directory's own prose.** See §9 |
| `run_all.sh` | the three fixed points. **Not** in `build.sh` — see that file for why |

## 1  The classification, in order

Each step refines the one before, and the first is **borrowed rather than re-spelled**,
because a second definition of "benign" is a second place for the definition to drift.

| # | bucket | what it means |
|---|---|---|
| 0 | `IDENTICAL` | the committed bytes and the regenerated bytes are equal |
| 1 | `BENIGN/timing+path` | `lib_f771.verdict_for` says `NOISE` — mg-f771's declared N1 (a checkout root) and N2 (decimal seconds), under N3 |
| 2 | `BENIGN/address+asof` | under **A1** (a `file.ext:NNN` line address) and **A2** (a git sha, an ISO date, a clock time) the texts become equivalent. mg-c824/mg-20ee's family |
| 3 | `VERDICT-STALE/token` | a verdict **token** appeared, vanished or changed. **The strong claim** |
| 3 | `VERDICT-STALE/number` | the token multiset is unchanged and a **number under one of them** moved. `A1 TOTAL BAD: 1 → 0` is this |
| 4 | `NON-VERDICT` | differs, but in no verdict line. **Corpus-size counts live here** |

### Why corpus-size is *not* masked, though the ticket names it a benign family

Masking corpus-size means masking **integers**, and `A1 TOTAL BAD: 1 → 0` is an integer. A
mask wide enough to eat `530 markdown file(s) → 531` and narrow enough to spare `TOTAL BAD:
1 → 0` is a mask about *nouns* — i.e. a list of the corpus nouns somebody has already looked
at. `lib_f771`'s own docstring names that failure: *"a wider normaliser is an unfalsifiable
escape hatch — an operator facing a real disagreement can silence it by widening the rule,
and nothing in the machinery tells that edit from a correct one."*

So corpus-size is **not proven benign here**. It falls into `NON-VERDICT` and is counted
there. **Nothing in the headline depends on that choice**, because the headline is defined by
*movement in verdict lines* and not by what is left over.

## 2  The token set is the instrument, so it is quoted in full

`lib30bd.TOKENS` is a hand-typed literal, printed verbatim in `out_verdict_staleness.txt` §2.
A line is a **verdict line** iff, after normalisation, it contains at least one token **as a
whole word**, **case-sensitively**. The case rule is most of the selectivity: this corpus
writes graded outcomes in capitals (`*** MISSED ***`, `VERDICT: RED`, `TOTAL BAD: 1`,
`CAUGHT`, `HELD`) and writes prose in sentence case.

**Derived, not guessed.** The candidates came from the ALL-CAPS frequency table over all
1051 tracked transcripts at `f2117f1`, ranked by how many files carry them:

```
PASS 3057/225   TOTAL 630/355   FAIL 613/162   GREEN 596/117   BAD 556/294
FIRES 530/72    VERDICT 493/246 REPRODUCES 492/35  CAUGHT 477/43  REFUTED 470/112
RED 414/119     FAILS 390/109   FALSE 369/163   DIFFERS 308/40   HELD 3488/39

… plus the `*** … ***` marker census:
MISS 33   MISSED 19   FAILED 13   FALSE 8   EXTENT WIDER 5   GREEN 5
```

What was then **dropped by hand** is the half that is only ever prose emphasis in these
transcripts' headers: `THE`, `AND`, `NOT`, `THIS`, `EVERY`, `STATE`, `README`, `HEAD`,
`BOTH`, `SAME`, …

**Both blocks above are quotations of a run nobody kept**, and §9's arm reports them as
such rather than grading them. That is not tidiness: §2 is the instrument, this derivation
is the whole justification for it, and a justification nothing regenerates is in exactly the
class this directory counts. It is remainder, and it is filed rather than absorbed.

**A transcript is verdict-stale iff the sorted multiset of its verdict lines differs**
between the committed copy and the regeneration. *Sorted*, so a verdict that only moved down
the page because an unrelated section grew is **not** a verdict that moved (world W15).

### What the choice costs, both ways — stated rather than discovered

* **over-inclusion.** A corpus-size count sharing a line with a token (`PASS — 530 file(s)`)
  reads as a verdict move. That is why the bucket is **split**: `token` is the strong claim,
  `number` is not. World **W18** is that cost, planted on purpose.
* **under-inclusion.** A verdict stated in a word nobody put on the list, or in lower case, is
  invisible here. This instrument cannot tell you how many those are — which is exactly what
  makes the token set the instrument and not a detail.

## 3  The two boundary worlds, and the one that was wrong first

`selftest_30bd.py` plants 19 worlds. **Five must come out benign** (W1 timing, W2 checkout
root, W3 line address, W4 sha, W5 date/clock) and those five are the entire reason this is
not a re-run of mg-20ee's census under a new name: a classifier that graded any of them a
verdict move would re-report the population that census already measured.

Two are boundaries, and **the first version of the address mask failed one of them**:

* **W12** — `A1 TOTAL BAD:1 → 0`, no space after the colon. The first `ADDRESS` regex was
  `(?<=[\w./-]):\d+\b`, and it ate this. **Measured, not feared:** under that regex W12
  classifies `BENIGN/address+asof` — i.e. the naive mask turns **the exact number this whole
  ticket is about** into a benign address move. The shipped regex requires a dot-extension or
  a slash in front of the colon, and W3 (`build.sh:342 → :352`) holds it wide enough to still
  do its job.
* **W13** — an address that moves **on a verdict line** must stay benign. Without this, every
  one of mg-20ee's 32 pinnings would be re-reported here as a verdict move.

## 4  The sandbox had to be faithful, and the first one was not

`sweep.py` runs each suite in its own `git clone --local --shared` of this worktree, rather
than `git checkout`-ing in place the way mg-20ee's `ground_truth.sh` does. Three reasons, in
increasing order of what they cost when ignored: `ground_truth.sh` restores only `$d`, so a
suite that writes outside its own directory leaks into the next measurement; these suites
**mutate the worktree they run in** and some exit non-zero half way; and it is the only way
to run more than one at a time, sequential being about five hours.

**The first sandbox lied, and the gate is what caught it.** A plain clone of a polecat
worktree has no local `main` branch, only `origin/main`. Run under that sandbox, `./build.sh`
at HEAD came back **RED, exit 1**, with

```
mg-f771 g0:   DISAGREES code/rendered_twin_pin_9bc2/out_control.txt
    - ancestor of main        : yes
    + ancestor of main        : (no such ref in this checkout)
    - twin  …  9455 bytes
    + twin  …  9482 bytes
```

Two disagreements, both of them the sandbox talking about itself — the second only because it
carries the first one's byte count. With `git branch main origin/main` in the clone, **the
same gate at the same commit is GREEN, exit 0**. That is the fidelity control, and it is a
run rather than an argument. Nothing in this instrument is borrowed from the subject under
audit, which is this estate's own recurring defect.

A second fidelity check, on real data rather than on the gate: `code/species_extent_d633`'s
`e2_crosssection.py` was run once in the sandbox and once in this worktree and the two
outputs are **byte-identical** (both exit 1, both `E2 TOTAL BAD: 5`).

### Two rows the harness must not grade, and one line that cost a two-hour sweep

**A run that did not finish is not evidence.** Two ways that happens, and both were measured
rather than anticipated:

* **Killed at the limit.** 22 of 187 suites hit the 900 s cap. A process cut off mid-write
  leaves a transcript that may be half written, and comparing *that* against the committed
  copy is **the harness accusing the corpus of its own truncation** — mg-479c's defect
  exactly, where a redirect handed mg-f771 a half-written file and f771 correctly graded
  `DISAGREES` about a redness the harness had caused. Those rows are `UNUSABLE/ungraded`.
* **Refused.** Exit 2. That is not this instrument's invention: `build.sh` prints the
  convention in its own footer — `0 green · 1 a control fired · 2 refused/broken` — and a
  transcript from a run that declined is not a measurement of anything. **Exit 1 is *not* in
  this class**: in this corpus that means a control *fired*, which is a completed run with a
  finding, and treating it as unusable would discard most of the corpus.

Together these took the **first sweep's** figure down three times, all downward, before
anything was committed. **That sweep is not the one this directory ships, and this paragraph
used to say otherwise.** The `--only` bug two paragraphs below destroyed that record; the
sweep was retaken; §7's table is the retaken one and every figure in it is a function of
`sweep_30bd.jsonl`. The superseded chain is deliberately not restated here, because a
number written in a sentence beside a number written in a transcript is a second copy and
this is what happened to the first one — see §9.

**And one of the two showed up in the motivating instance itself.** `6cb9`'s
`a1_bothways.py` **refused (exit 2) under host load 40–50** in the full sweep, so the one
transcript this whole ticket rests on came back ungraded. Re-run alone on a single worker it
exits 0 and reproduces `p6e4f` exactly (`A1 TOTAL BAD: 1 → 0`). That re-run is a supported
operation — the record **appends** and `report.py` takes the **last record per directory**.

It is supported *now*. `sweep.py` opened its record `"w"`, so the `--only` re-measurement
**deleted the 187-suite record it was meant to correct**, and the sweep had to be taken
again. A harness whose repair operation destroys the thing being repaired is this estate's
own recurring shape, and it turned up inside the instrument that counts it. `--fresh` is now
the only way to truncate, and the comment on that line says what it cost.

**And the repaired mechanism was then used twice, on the second sweep, which is the only
evidence that it works.** `code/control_gate_724a` raised `OSError` — `No space left on
device`, the host filled up under other agents — mid-sweep, and one `--only` re-run
appended a clean row that the report picked up in place of the error, taking the record to
its full 187 suites without disturbing any other row. `report.py` also takes the **first**
header rather than the last, because `--fresh` truncates and every later header belongs to a
one-directory correction: taking the last one printed *"187 suites run, of 1 in the
population"* — an instrument reporting its own denominator from a correction to itself.

## 5  The runner-blind pass, and why it exists

`code/species_extent_audit_6cb9/run_all.sh` gates its three audit scripts behind a selftest
and `exit 1`s when the selftest fails. **It fails at HEAD today.** So a sweep that only runs
runners never regenerates `out_a1_bothways.txt` — **the one transcript in this corpus whose
verdict move was already known** — and would have reported the motivating instance as a
two-line selftest wobble.

An enumeration's blind spot is not a footnote when the thing it cannot see is the reason the
enumeration was commissioned. So pass 2 takes the producing command **out of the runner's own
text** (`python3 -B a1_bothways.py > out_a1_bothways.txt`) and runs it alone. A producer the
parser cannot see is recorded `unparsed` and is **not guessed at**; a per-directory cap is
recorded `capped` and is **named rather than silently dropped**.

## 6  What this method cannot see

Printed in full in `out_verdict_staleness.txt` §6, per the mayor's instruction to `p6e4f`.
In short:

1. **A transcript no suite regenerates cannot be checked this way.** Directories with no
   `run_all.sh` are outside every number here. This is mg-f771's own declared hole one level
   out.
2. **A runner that declines.** Pass 2 reaches the ones whose producer is a plain redirect in
   the runner; the rest stay unmeasured.
3. **Suites that did not finish** — timeouts and raises, listed by name.
4. **The token set is a choice**, and §2 states both of its biases.
5. **An enumeration only sees what it enumerates.** Everything here is a per-suite loop, so a
   transcript no loop entry reaches is invisible however the classifier is tuned. **The thing
   that catches what an enumeration misses is a whole-run before/after diff** — run the
   corpus, diff the tree, and read what moved without having decided in advance what could.
   mg-6cb9 was found that way and not by any enumeration, including this one.

## 7  What this does to the reported numbers

```
 54  presumed stale     mg-20ee's original, superseded
 32  already-stale      the census ground truth — AUTHORITATIVE FOR ADDRESSES
150  verdict-stale      this measurement, over a DIFFERENT population
     = 137 reachable by a runner (103 token, 34 number) + 13 reachable only by
       bypassing one.  Out of 665 transcripts a runner actually rewrote, against
```

**150 does not supersede 32 and it does not contain it.** They are counts of different
populations under different questions and neither is a correction of the other.

**The two are not nested and must not be added without saying so.** mg-20ee's 44 candidates
are the transcripts that carry a foreign `path:NNN`; this population is the transcripts whose
*graded statements* moved. A transcript can be in either, both, or neither —
`code/species_extent_audit_6cb9` is in the second and **not** in the first, which is why
nobody had counted it. Anything quoting 32 as "the staleness in the corpus" is quoting one of
two classes.

## 8  What this ticket does not do, and who has to

`mg-30bd` is tagged **`declares-remainder`**. It measures; it repairs nothing. These are left
open and named rather than left to be found — item 5 is mg-2959's, added by the arm in §9:

1. **Every entry in §4 and §5 needs an owner, per instance.** A batch repair is exactly what
   mg-20ee's method forbids — *"if a verdict moves, that is a finding; do not absorb it into a
   pinning commit"* — and it is why `p6e4f` refused to fold the 6cb9 move into its pinning
   branch.
2. **The population is measured once, at `f2117f1`, and it is not a fixed point.** There is no
   baseline, so there is nothing yet that can say *the list has grown*. Gating on that is the
   obvious successor and it needs a declared baseline this ticket does not have the standing
   to set.
3. **105 transcripts are UNGRADED and 22 suites timed out at 900 s** — 11.8% of the
   population produced no usable answer, so every count here is a floor. Re-taking the sweep
   at a higher limit on a quiet host is the cheapest way to move it, and the record now
   supports doing that one directory at a time.

4. **This directory is not in its own population, and the reason is mechanical rather than
   an exemption.** The sweep ran at the commit that carries this instrument's *sources* and
   none of its *transcripts* — an instrument is run before it is committed, which is
   mg-20ee's own `AS_OF` rule 2 — so `code/verdict_staleness_30bd` is a candidate directory
   with zero tracked `out_*.txt` and drops out of the population by the same test every
   other directory is measured by. The next sweep will include it. That is the right
   outcome and it is worth stating out loud: this instrument's own transcripts are subject
   to exactly the defect it counts.

5. **§2's derivation is a quotation of a run nobody kept.** mg-2959 added §9 and §9 reports
   it rather than grading it. The ALL-CAPS frequency table and the marker census are the
   whole justification for the token set — which §2 itself calls *the instrument* — and no
   script in this directory regenerates either. Re-taking that census at `f2117f1` and
   keeping it as a transcript is the repair; it is named here and not done.

## 9  The prose arm — mg-2959

`report.py` regenerates every figure in the **transcripts** on every run, so none of them can
go stale. Nothing regenerated the figures in the **prose**, and **four** of them were wrong:
§4's account of the first sweep, §4's suite arithmetic, `run_all.sh`'s own header, and §4's
timeout count. **This arm catches three of the four**, and which one it misses is the
interesting part — see the declared hole below. The three are quoted verbatim inside
`prose_30bd.py` as controls, so the repair is what makes them absent from the findings list
rather than a claim that they never happened.

**The rule is borrowed and not re-spelled.** `lib7522.figures()` is this estate's rule for
*is this number a figure, a measurement that must be backed by a transcript?*, and
`lib7522.transcript_figures()` for *what does a transcript back?*. Both are imported, for the
same reason `lib30bd` imports `lib_f771.verdict_for` rather than re-implementing "benign".
mg-7522's verdict is taken word for word — *a USE is BACKED when every figure on its line
appears in one of this tree's committed transcripts, and UNBACKED otherwise* — and its
restriction to lines carrying a strength marker is **not** taken, because none of the three
defects stands on one.

**Two polarities, and the second is `report.py`'s own.** A figure outside a fenced block is
in the README's own voice and is **graded**; a finding exits 1. A figure inside a fence is a
**quotation**, this arm cannot tell a stale quotation from a faithful one, and it is counted
and listed and **not graded** — the polarity `report.py` gives a run that was killed or
refused, and for the same reason: unmeasured is not clean. A *backed* figure inside a fence is
still reported as backed, so §7's table is positively checked rather than merely
un-condemned.

**And the arm excludes its own transcript from its own backing corpus, by name.** It prints
the figures it finds unbacked; left in the corpus, each finding would be backed on the next
run by the report of its being unbacked, and the arm would go green with the prose still
wrong. That is `sweep.py`'s `--only` defect one surface out, and P4c plants it rather than
asserting it.

**Its declared hole, and it is the more interesting half.** The rule is *set membership*: a
number printed anywhere in a transcript of this directory backs the same number written
anywhere in the prose. So a figure that is right in the set and wrong in its role is
invisible — **measured on the real instance**, §4's `17 of 187 suites` (the record says 22)
did **not** fire, because the report prints a 17 somewhere else. That one was found by reading
the record. Role needs a per-figure anchor quoted from the prose, and such an anchor rots
silently the moment anybody rewords the sentence, which is why this arm is a membership test
and says so instead.

## 10  The owners arm, and the baseline it makes possible — mg-937c

§8's items 1 and 2 are **one** piece of work and this section is why. Item 1 wants an owner
per instance for all 150; item 2 wants a baseline so that something can say *the list has
grown*. Set the baseline without item 1 and you have declared a number nobody has read —
which is a number that launders whatever was true on the day it was taken, and is exactly
why mg-30bd refused to set one. So `OWNERS.json` is **both**: one row per verdict-stale
transcript, each carrying a hand-assigned `cause` and `disposition`, and the baseline *is*
that list. **You cannot declare it without naming a cause for every row.**

`owners_937c.py` grades it against the record through `report.py`'s own `population()` and
`stale_set()` — **imported, not paraphrased**, which is the reason those two functions were
lifted out of `main` in the same commit. Two copies of *which transcripts are stale* drift
apart into a baseline that is complete against a classification the report no longer
performs; the control that the lift changed nothing is that `out_verdict_staleness.txt`
reproduces byte-identically across it.

**What is checkable and what is not, said rather than implied.** Four things are
falsifiable and three of them are hand fields: that every stale entry has a row, that no
row's class has strengthened `number → token`, that `read` matches whether the record
quotes the whole move or caps it at six lines, and that `cause: RECORD-DISAGREES` agrees
with the record's own disagreement **in both directions**. Nothing checks that a cause is
the *right* cause — an arm implying otherwise would be the laundering the file exists to
avoid — and `owner` is derived from the directory name, so it is an **address, not a
consent**.

### The structural answer to "who owns these", which is not a person

`./build.sh` runs **9** suites. The record ran **187**. **Zero** of the 150 sit in a
directory the merge gate runs, so no branch has ever been told about any of them. That also
reconciles the two facts that look like a contradiction: mg-f771's g0 — which *is* the
whole-run before/after diff §6.6 asks for — is green over the whole tree, because it can
only compare transcripts the gate's own run rewrote. A green whole-run diff over a ninth of
the corpus and 150 stale transcripts in the other eight ninths are the same measurement.

### Six of the 150 are not findings about the corpus, and reading them is how that was found

- `code/audit_c067/out_c1_rebase.txt` opens with **`DO NOT RE-RUN THIS`** and explains that
  a re-run writes a false `0` over a true `5`, because its producer pairs commits by subject
  inside `git log -n 40`. The sweep re-ran it and graded the result. A false positive by the
  subject's own declaration, and the classifier has no notion of such a declaration.
- `code/mirror_staleness_cdd5/out_selftest_cdd5.txt` prints `%r` of a `set` of `str`.
  **Measured, not inferred:** six runs on an unchanged tree gave at least three orderings of
  the same three elements. It cannot be a fixed point for anybody; sorting ends it.
- **Three** rows where the record contradicts itself and the disagreeing observation is not
  the owner's — `report.py` now prints a `NOTE` on all eleven such entries (see below).
- `code/verdict_delivery_bf3f/`'s four transcripts read the live mg verdict stream, so no
  commit can make them reproduce.

### Eleven entries whose own record disagrees, annotated and *not* reclassified

113 rewritten transcripts were regenerated by more than one suite. `buckets` keeps the
strongest bucket, which is the right headline and is silent about disagreement. For eleven
§4 entries there is one; for **two** the observation saying IDENTICAL is the transcript's
**own owning runner**, and for **one** neither observation is the owner's at all. Those are
annotated and left in the count. Dropping them would move 137 → 134 and 150 → 147, and
those figures are quoted in this README, in §7, in mg-2959's commit message and in mg-937c's
own title — *which* observation is authoritative is a decision about the corpus and belongs
to the instance's owner, whereas *that a decision is owed* is a fact about the record, and
this is the report of the record.

### Not in `build.sh`, and now for a different reason

§8 item 2's precondition — a committed baseline — is discharged, so this is a decision
rather than an omission. The record is frozen; the arm moves only when somebody edits the
record or `OWNERS.json`, and that somebody is running this suite deliberately. Gating would
buy catching an appended `--only` re-measurement whose author did not look — real, but the
same author in the same commit — and would cost putting a suite that reports 150 findings
about other directories on every branch's critical path. Priced and declined here rather
than left silent.

### What this leaves, including one instance of §9's own declared hole

The 105 UNGRADED rows, the 22 timed-out suites and the 219 unparsed producers are outside
the baseline entirely, and re-measuring them is *how this list grows* — that is the growth
the arm now exists to catch. §6.6 is unchanged and still owed; what §1 of the arm adds is
where to point that diff, at the 178 suites the gate does not run. And `report.py`'s
`<sha> <subject>` detector needs a masked sha at line start, so a walk printing
`HEAD's subject : <subject>` is missed: **4 of the 8** rows this baseline calls
`HISTORY-WALK` carry no `NOTE` in §4, measured by the arm rather than counted by hand.
Finally, the pointer `§10` two paragraphs up is a live instance of §9's declared role-vs-set
hole — mg-7522's rule reads the `10` as a figure and finds it backed by the arm's ten
planted worlds, which is set membership working exactly as §9 says it does.
