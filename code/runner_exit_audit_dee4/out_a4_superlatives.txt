A4d  THE CLAIM RULE IS LINE-LOCAL, AND THE STRONGEST CLAIM WRAPPED
==============================================================================

  S3a scores a CLAIM as a LINE carrying both a marker and a number.
  In a hard-wrapped markdown paragraph the marker and its figure land
  on different lines routinely.  The claim this audit most wanted to
  check is exactly such a case:

      OUTCOMES.md:88  `wc -c < FILE` counts the same bytes the pipeline did, verified against the
                     ^ marker `verified`, digits on this line: False
      OUTCOMES.md:89  pre-repair output (`0 / 0 / 0 / 0 / 2111 / 0`, unchanged).
                     ^ the figure.  A line-local rule sees
                       neither line as a claim.

  THE SAME RULE WITH A ONE-LINE WINDOW, over both populations:

      mg-c2b3's artifacts (S3a's own subject)    window 0:  20   window 1:  24   (+4)
          mg-7522 published 20 for this population.
      mg-7522's own artifacts                    window 0:  31   window 1:  40   (+9)

  DOES ANY PROBE IN MG-7522'S TREE PRODUCE THAT FIGURE?  Asked of the
  OUTPUT, not of the source.  A grep of the source for `wc -c` scores
  the comment that explains why `wc -c` is no longer in a pipeline --
  which is the mention-for-occurrence defect mg-7522 recorded three
  times in its own OUTCOMES.md.  So the question is put to the
  committed transcripts instead: does the number appear in any of them?

      committed transcripts in mg-7522's tree             6
      of those printing the figure `2111`                 0

  SO: the marker is doing the work of an instrument, in the tree
  whose thesis is that markers should not.  A2d ran both arms on
  the same inputs and the claim HOLDS -- which is the outcome that
  makes this reportable rather than damning.  `verified` was
  checkable, was not checked by its author, and turned out true.
