D  THE BACKSTOP, WHICH IS NOT THIS CENSUS
------------------------------------------------------------------------------

  Every name above came from a grep for a filename, so a consumer
  reached by a constructed path, by a wrapper more than one hop
  away, or from outside this repository IS NOT IN IT.  The census
  cannot check itself.  What can: run each consumer BEFORE and
  AFTER the pin and diff the two outputs.  A missed consumer shows
  up in that diff whether or not it was enumerated -- provided you
  run the suite it lives in.

  For each instrument in section C:

      git stash push -- <the pinned file>   # or check out the
                                            # pre-pin revision
      sh <dir>/run_all.sh > /tmp/pre.txt 2>&1
      git stash pop
      sh <dir>/run_all.sh > /tmp/post.txt 2>&1
      diff /tmp/pre.txt /tmp/post.txt

  An EMPTY diff is the result you want and it is a MEASUREMENT.
  A non-empty one is either the pin reaching a consumer -- fix the
  consumer or the pin, do not pin over it -- or that consumer's
  own pre-existing staleness, which is a FINDING and belongs in
  its own work item rather than in a pinning commit.

  AND THE LIMIT THAT DOES NOT GO AWAY, PRINTED BECAUSE IT IS THE
  LOAD-BEARING SENTENCE IN THIS RUN: a consumer this census misses
  AND that nobody runs is INVISIBLE, and no instrument in this
  directory fixes that.  Six of nine consumers were found affected
  by RUNNING them.  That is a statistic about things that were run,
  so it cannot license `a missed consumer would announce itself`.
  THE BACKSTOP ABOVE IS THE LOAD-BEARING HALF; THIS CENSUS IS A
