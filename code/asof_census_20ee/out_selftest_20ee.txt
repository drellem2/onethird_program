POSITIVE CONTROLS — shapes the classifier MUST count
------------------------------------------------------------------------------
  PASS P1 computed address into a foreign doc               
        the instrument reads the file and the token is not in its source — the defect mg-20ee repairs.
  PASS P2 computed address into another instrument's source 
        foreignness is about the OWNING DIRECTORY, not about the file extension.

NEGATIVE CONTROLS — shapes it MUST NOT count.  These carry the weight,
because the declared bias of this census is that it OVER-counts.
------------------------------------------------------------------------------
  PASS N1 an address into the instrument's OWN directory    
        not foreign, so not this defect: the instrument owns what it addresses and nobody else can move it under it.
  PASS N2 a HARDCODED citation, token present in the source 
        a stale-citation hazard and a DIFFERENT repair — pinning the corpus would not fix a number typed by hand.
  PASS N3 a file the instrument never reads                 
        an echo of someone else's prose citation, not a computed address.
  PASS N4 an untracked path                                 
        UNDER-COUNT, DECLARED AND CONFIRMED: addresses outside this repository are invisible to git and so to this census. a4_census's mg-3ce3 probe is one such. The floor is real and this control is why it is a floor.

THE CONTROL THAT CONFIRMS A KNOWN DEFECT RATHER THAN A REPAIR
------------------------------------------------------------------------------
  PASS N5 an instrument that ALREADY reads at a declared commit 
        COUNTED ANYWAY — this is the census's second declared over-count, planted so it cannot be forgotten. code/state_audit_6a2f is the real instance. If somebody teaches the classifier to see pinned reads this control FAILS, and that is the signal to update census.py's docstring and out_ground_truth.txt together.

CONTROLS ON consumers.py — mg-20ee's THIRD CONDITION (mg-6e4f)
------------------------------------------------------------------------------

  The consumer census decides, for a file that NAMES a script, whether
  it EXECUTES it and whether it passes a path.  A pin disturbs the
  no-arg callers and not the others, so the whole value of the
  instrument is in telling those three apart.  Planted lines, because a
  classifier only ever run against the real corpus has no evidence it
  can distinguish anything.

  PASS C1 an exec with no path argument                     
        the shape that GETS the pinned default and must be re-measured. kern6cb9.py, kern4700.py and v2_layer2.py are the real instances.
  PASS C2 an exec that passes a scratch path                
        the caller chose the tree, so the pin does not reach it. MEASURED on the real instance: species_audit_73df/c4_scope.py is byte-identical with and without the pin.
  PASS C3 a name with no exec token near it                 
        THE CONTROL THAT CONFIRMS A KNOWN DEFECT RATHER THAN A REPAIR. This is e1_extents.py's real line. E1 DOES execute it -- through two variables and a tracer -- and this census CANNOT SEE THAT. It lands in the residue, and section C's work-list is C1 PLUS C2 for exactly this reason. If somebody teaches the rule to follow variables, this control FAILS, and that is the signal to update the docstring's blind-spot list and section C's warning together. DO NOT `FIX` THIS CONTROL BY MAKING THE CENSUS PASS IT: a control that confirms a DEFECT rather than a repair is unusual, and the failing case IS the assertion. It is here in the form N4 and N5 already use one directory up, for the same reason -- a declared bias that no control holds in place is a sentence that goes quietly false.
  PASS C4 the exec token may stand on a LATER line          
        a two-line call is the common formatting in this repository and a same-line-only rule would have reported half the estate as inert.

THE CONTROL FOR THE CRASH THAT MADE THIS CENSUS UNUSABLE (mg-4020)
------------------------------------------------------------------------------

  `git grep` exits 1 for NO MATCH and 2+ for a real error, and this
  census read every non-zero as fatal.  So a subject script that
  nothing outside its own directory names -- a library, a numbered
  step, or ANY run_all.sh, since a shared basename is searched by full
  path -- took the whole run down.  MEASURED: it died on 23 of the 27
  instruments still on mg-20ee's pinning work-list, and ran on 4, one
  of which is the single subject it was built against.  The evidence
  that it worked came entirely from the one directory where every
  script happened to be named elsewhere.

  PASS C5 a needle nothing outside the subject names        
        FINDING NOTHING IS AN ANSWER, and it is the ordinary answer for a library or a numbered step. Before this it was a crash, after a correct-looking header had already printed. THE NEEDLE IS ASSEMBLED FROM PIECES: spelled as one literal this control FOUND ITSELF the moment it was committed, because it is a tracked *.py and this rule greps tracked *.py.
  PASS C6 a REAL git error is still fatal                   
        THE NEGATIVE HALF, AND IT CARRIES THE WEIGHT. Widening the tolerance to `any non-zero means empty` would turn a bad pathspec or a broken index into a census of nothing that reports `none` in section A -- which reads exactly like a subject no instrument consumes. Only rc 1 is no-match; rc 2 and above stays fatal.
  PASS C7 a needle that is a SUFFIX of a longer filename    
        MEASURED, and found by running condition 3 against the census's OWN directory: `census.py` is a UNIQUE basename, so it was searched for by basename, and a substring test matched every numbered step in the estate whose name ENDS in it. 76 of 81 occurrences were this. THE INVERSE OF `A BASENAME IS NOT A NAME`, which fixes a basename SHARED by many files -- that rule cannot see this one, because census.py really is unique among tracked paths.
  PASS C8 a FULL-PATH needle still matches after a slash    
        THE NEGATIVE HALF OF C7, AND IT CARRIES THE WEIGHT. `/` must be ALLOWED as a preceding character or a full-path needle would never match and EVERY SHARED BASENAME would go silent -- converting a loud over-count into the exact under-count section D warns about. A word-boundary regex would have done that.

CONTROLS ON pinnable.py — mg-20ee's CONDITION 0 (mg-4020)
------------------------------------------------------------------------------

  Conditions 1-3 all assume a pin is the remedy.  pinnable.py asks
  whether it is, by classifying a drift the caller has already
  produced.  Planted diffs and an INJECTED resolver, so the controls
  do not depend on which commits this clone happens to contain.

  PASS P3 an IGNORED path in a changed line                 
        species_repair_a4ef's real line. .gitignore's `__pycache__/` carries a TRAILING SLASH and matches directories only, so check-ignore says NO to this path as written — both forms are tested, and a rule that tested one would have missed the instance it was built from.
  PASS N6 a TRACKED path in a changed line                  
        landscape_repair_1953's real line, and the contrast that makes R1 mean anything: a pin CAN restore a tracked file's old content, so this drift is mg-20ee's remedy working as designed and must not be swept into `no pin reaches it`.
  PASS N7 a diff HEADER is not an address                   
        every unified diff names its own file twice at the top. Counting those would make each instrument address itself and put a path in EVERY diff, which is the shape that turns a prefilter into noise.
  PASS P4 a declared revision the repository RESOLVES       
        state_relocation_audit_b0ae's real line — the instrument that is ALREADY PINNED and drifts anyway.
  PASS N8 a hex-SHAPED english word, not resolvable         
        THE NEGATIVE HALF, AND IT CARRIES THE WEIGHT. `defaced` is seven characters and every one of them is a hex digit. RESOLUTION is what makes R2 a rule rather than a regex: without `git cat-file -e` this rule reports prose as a pin, and R2's whole claim is that SOMEBODY DECLARED A REVISION.

CONTROLS ON R3 — THE UNORDERED WALK (mg-0e77)
------------------------------------------------------------------------------

  R3 says a subject enumerates the filesystem, so its transcript's
  LINE ORDER is in no commit and a correct pin will permute it.  The
  NEGATIVE half is the load-bearing one: `git grep` is the form R3
  exists to recommend, and a rule that fired on it would tell every
  repaired instrument in the estate that it is still defective.

  PASS P5 `grep -r` spelled as a Python LIST                
        landscape_repair_audit_3b51's real line, before this branch. The two tokens are separated by a quote, a comma and a space, so a pattern requiring `grep -r` adjacently sees nothing — and the ONLY subject this rule has ever had is spelled that way.
  PASS P6 `grep -rn` spelled as a SHELL command             
        the same read in a run_all.sh. Half this estate's corpus reads are shell and half are Python; a rule that saw one spelling would report `none` for the other and look like a clean subject.
  PASS N9 `git grep` is an ORDERED READ OF A COMMIT         
        THE NEGATIVE HALF, AND IT CARRIES THE WEIGHT. This is the repaired line R3 exists to recommend, and it contains the literal `grep` plus a `-n` flag. git SORTS its output and reads a COMMIT, which is the whole point; a rule that fired here would condemn the repair as the defect and there would be nothing left to advise.
  PASS N10 a walk the subject has already SORTED            
        an instrument that ordered its own walk has already removed the difference R3 warns about, and the transcript is repo-valued without any pin. Firing here would price a repair that is already paid.
  PASS N18 prose quoting the INVOCATION, flag and all — FIRES (mg-885d) 
        A KNOWN-DEFECT CONTROL, in the form N4, N5 and C3 already take. N11 below plants the BARE word and passes; the rule matches the word plus a following short-flag cluster, so a sentence NAMING the invocation is a shape N11 does not reach. MEASURED across the estate at 12aa5f8 rather than supposed: 3 of R3's 92 hits sit on comment lines, and BOTH hits in audit_scope_text.py — THE INSTRUMENT TRANCHE 4 PINNED — are comments explaining the defect it already repaired, so condition 0 still tells a repaired instrument to expect a permuted transcript. That is N9's own rationale failing by PROSE instead of by the git form. Asserted rather than repaired, because R3 is mg-0e77's rule: teach it to see prose and this control goes RED, which is the signal to update its self-hit count.
  PASS N11 the word `grep` in prose                         
        R3 reads the subject's SCRIPTS, which in this estate carry more commentary than code — every docstring in this directory names its own method. A rule that matched the word rather than the invocation would fire on the file explaining it.

CONTROLS ON permuted.py — mg-20ee's CONDITION 2 (mg-885d)
------------------------------------------------------------------------------

  R3 established that a CORRECT pin permutes its transcript, so
  condition 2 was re-read as SET-IDENTITY PLUS A DECLARED PERMUTATION.
  permuted.py is the first thing that can MEASURE that reading, and it
  amends it: a SET forgets multiplicity, so the test is a BAG.  P11 is
  the control that carries this whole file's weight — it is the case
  the wording as written gets WRONG, and it is silent when it does.

  PASS P11 a line's MULTIPLICITY changed — SET says nothing happened 
        THE CONTROL THIS INSTRUMENT EXISTS FOR. mg-3b51's own pinned transcript prints one address twice and mg-1953's prints one three times; a pin that dropped one occurrence moves an ADDRESS and the COUNT it belongs to, and `set-identity` — the wording condition 2 was amended to — scores it IDENTICAL. 123 tracked transcripts carry a repeated line naming a path, so this is a shape the estate has.
  PASS P12 a pure PERMUTATION is bag-identical and not byte-identical 
        the case R3 predicts for every correct pin of a `grep -r` corpus: `git grep <rev>` sorts, the walk did not, and no line's content changed. Scored byte-wise this is a FAILED pin; it is a clean one.
  PASS N15 an unchanged transcript is BYTE-identical        
        the negative half of P12, and the reason condition 2 is not simply loosened: byte-identity still holds where it can, and ./build.sh and mg-f771's fixed point are RIGHT to keep comparing bytes. R3's permutation appears at the PIN TRANSITION, not run to run.
  PASS P13 a MOVED VERDICT is not a permutation and is not hidden by one 
        3b51's and 1953's transcripts differ on exactly this line BY DESIGN. A comparator that reported `permuted` for a shuffle that also moved a verdict would absorb mg-20ee's own discrimination — `if a verdict moves, that is a FINDING` — into a pass.
  PASS N16 a DECLARED residue is excused                    
        a pin ADDS an AS_OF block, and mg-20ee's discrimination expressly allows it to move. Without this the correct outcome of every pin would print as a finding, and the instrument would be unusable on the only case it is for.
  PASS P14 a declaration is matched BY OCCURRENCE, not as a set 
        THE NEGATIVE HALF OF N16 AND IT CARRIES THE WEIGHT. Declaring a line once must not excuse it twice, or P11's defect returns one level up — inside the mechanism built to catch it. A set-shaped declaration would pass a pin that dropped one of three identical addresses.
  PASS P15 a declaration written from the DIFF traces to nothing 
        THIS FILE'S OWN DEFECT, CONTROLLED. `--declare` is an artifact of the same kind as the thing it scores: a declaration written by reading the diff excuses that diff entirely and turns CONTENT MOVED into a silent pass. Provenance is what stops that being invisible, and both declarations shipped here are traced to the pin's own source or its published record — never to the diff.
  PASS N17 an AS_OF header line traces to the pin's own SOURCE 
        audit_scope_text.py:104 prints exactly this, with the revision as a %s. The pin's author wrote the header in CODE before any transcript existed, which is why `script` is the strong half of provenance and `record` — a token quoted in prose — is declared weak.
