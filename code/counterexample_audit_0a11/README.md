# `counterexample_audit_0a11` — the instrument for the mg-0a11 audit of mg-dea5

Produces every number in `docs/OneThird-Counterexample-Under-The-Action-IndependentAudit-mg0a11.md`.

```
./run_all.sh          # ~13 minutes cold, seconds warm, pure Python 3, no dependencies
```

**Independence.** Imports nothing from `code/counterexample_probe_24a3/` (the target, mg-24a3),
`code/counterexample_audit_a7b4/` (the first audit) or `code/counterexample_repair_dea5/` (the subject,
mg-dea5), and shares no code with any of them. Every object is rebuilt from the definitions printed in the
two documents, in exact integer / rational arithmetic.

**Routes deliberately not the subject's.**

* posets are generated by adjoining a **new maximal element above an order ideal**;
* isomorph rejection is by an exact canonical code — the lexicographic minimum, over the permutations
  compatible with a Weisfeiler-Leman colour refinement, of the pair-symbol sequence — with `|Aut(P)|` read
  off as the number of permutations attaining it. Checked against **A000112** *and* **A001035** to `n = 8`
  (16999 classes, 431723379 labelled posets). The second sequence is the load-bearing one: a class count
  alone would be satisfied by an enumerator that over-merges and under-merges by the same amount;
* `p(x,y)` is counted by **splitting each linear extension at the position of `x`** —
  `Σ_{S ideal, x maximal in S, y ∉ S} e(P|_{S−x}) · e(P|_{V−S})` — never by building an augmented poset;
* multiplicities `m_X` come from the **defining triangular system** `Σ_{Y ≤ X} m_Y = Π_{B ∈ X} e(P|_B)`
  solved downward over the actual refinements of `X`, **not** from the subject's multiplicativity Lemma,
  which is one of the things being audited. That the two agree on every `qmass` reported is therefore
  evidence about the Lemma rather than an assumption of it;
* the `e = 9` family is carried to `n = 11` by a targeted exhaustive enumeration of the posets with
  `e(P) ≤ 9`, a class closed under deleting a maximal element.

**Randomness.** One seeded sampler (`20260730`) in `check_cycles.py`, used only to corroborate that a
sampling negative at `n = 9` is uninformative at that sample size. Everything else is exhaustive.

## Files

| file | what |
|---|---|
| `kernel.py` | posets, enumeration up to isomorphism, `e`, `p(x,y)`, `δ`, tie-freeness, `L*`, cycles, levels, `m_X`, `qmass`, `qfrac` |
| `check_population.py` | the population, every `e`-group containing an extremal poset, the exact `p`-values by full enumeration of `C(N,k)` labellings → `out_population.txt` |
| `check_independence.py` | **the primary finding** — cut elements, cores, and how many *independent* chances the separation had to fail → `out_independence.txt` |
| `check_cycles.py` | the negatives, the exhaustive `n ≤ 8` sweep, the witnesses at 9/10/11, and an attack on each → `out_cycles.txt` |
| `check_deflation.py` | the subject's section 5, which is beyond its brief → `out_deflation.txt` |
| `check_locator.py` | 14 meaning-changing mutations against the subject's two doc-checkers, plus 4 self-mutations against this audit's own → `out_locator.txt` |
| `check_powered.py` | the powered test cell by cell, the saturation control, the raw effect table, attainability → `out_powered.txt` |
| `check_doc_audit.py` | this audit's prose against these outputs, each figure against **one** file and inside **one** section → `out_check_doc.txt` |

## Reading the output

`out_independence.txt` is the primary deliverable: it is the one place this audit says something the subject
does not. `out_locator.txt` should be read first — if the four self-mutations at the bottom do not fire, then
`check_doc_audit.py` is not a control and nothing certified by it is certified.

`check_powered.py` caches the whole-population `qmass` pass in `.records.pkl` (gitignored). Delete it to force
a cold rebuild; that is the 12 minutes.
