S1a  THE TWO VALUES ARE ONE CORPUS UNDER TWO WRITE REGIMES
==========================================================================

  A probe that censuses `code/*/out_*.txt` is inside its own
  population.  What its census reads therefore depends on how its own
  transcript is being written AT THE MOMENT IT RUNS:

      a plain `>`      truncates the file before python starts, so the
                       probe reads its own transcript as EMPTY;
      `.new` + `mv`    leaves the previous run's transcript in place,
                       so the probe reads its own PREVIOUS output.

  mg-bf79 introduced the second; mg-9160's `run_all.sh` adopts it and
  says why, in its own comment, naming this as `the arc's defect #7`.
  Both disciplines are in the arc RIGHT NOW, and a figure produced
  under one is not the figure produced under the other.

S1c  THE ORBIT, ITERATED IN MEMORY, WITH DESIGNED-PERIOD CONTROLS
==========================================================================

  `T -> render(census(corpus + T))`, from the empty transcript, over
  the REAL corpus on this disk.  In memory, because a probe that
  iterates by writing cannot be run twice without changing its own
  answer -- which is the disease.

  population: the 832 transcripts on disk at HEAD, plus one virtual transcript   @5c8f879

      transcript shape                                        start   period
      r_fixed -- the shape EVERY arc probe has                    2        1
      make_cycler(P=2) -- CONTROL, shape follows value            2        2
      make_cycler(P=3) -- CONTROL, shape follows value            2        3
      make_cycler(P=5) -- CONTROL, shape follows value            2        5

      period 1 is a FIXED POINT.  The three controls are transcript
      shapes whose ROW COUNT depends on the value they report; each is
      built to a named period and the detector returns that period, so
      `period 1` above is a measurement and not a default.

      the fixed point r_fixed lands on:      833   2098    504   1283    616
      the corpus without any observer:       832   2093    504   1283    614

  THE SUFFICIENT CONDITION, and it is the whole explanation:

      if a probe prints a number of count rows that does not depend on
      the VALUES it prints, then one application of the map fixes the
      corpus row count, and every later application is the identity.

  Every probe in `mg-9160` and `mg-03d1` has that shape.  So does every
  probe here.  SELF-INCLUSION ALONE CONVERGES; what does not converge
  is a corpus that GROWS, and that is S2.

S1d  WHAT THIS PROBE CANNOT DO, AND WHICH ONE DOES IT
==========================================================================

  Everything above is computed from the corpus ON THIS DISK, without
  running anything.  That is deliberate -- my ticket forbids
  regenerating another tree's transcripts, and a probe in `run_all.sh`
  that ran mg-03d1's suite three times would take a quarter of an hour
  and rewrite six files it does not own.

  So the two arms that need actual runs live in `x1_orbit.py`, which
  clones this repository into a directory you name and refuses to
  start if that directory is inside it:

      X1a  mg-9160's suite iterated from c9160's own corpus state
      X1b  the two regimes at c9160's own ref -- 1984 and 1966 out of
           ONE corpus
      X1c  mg-03d1's suite iterated at HEAD

  Its transcript is committed as `out_x1_orbit.txt`.  IT IS NOT
  REGENERATED BY `run_all.sh`, so it is a dated measurement and it will
  go stale exactly the way every other figure in this arc does.  That
  is stated here rather than discovered later, and S4 gives it a class.
