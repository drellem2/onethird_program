D.  BUDGETS, NAMED, WITH THE MACHINE THEY ASSUME
------------------------------------------------------------------------------
A budget is in ELEMENTARY OPERATIONS (DP cell updates).  Big-integer costs
are not charged, so every reach below is an OVER-estimate.

  this 10-core box, 24 h, optimal C at 1e9 cell-ops/s/core
      budget 2^49.6 ops   ->   REACH  n = 13  (LOW model)   n = 13  (KR model)

  1000-core cluster, one month, same rate
      budget 2^61.2 ops   ->   REACH  n = 15  (LOW model)   n = 15  (KR model)

  1e6 cores, one year -- a national-scale allocation, and larger than
     any computation ever run on this problem
      budget 2^74.7 ops   ->   REACH  n = 17  (LOW model)   n = 17  (KR model)

  every CPU on Earth for a decade (~1e28 ops) -- not a machine, a ceiling
      budget 2^93.0 ops   ->   REACH  n = 19  (LOW model)   n = 19  (KR model)

  LANDAUER: the Sun's entire energy output over the age of the universe,
     at kT ln2 per irreversible bit (~5e64 ops) -- a physical limit, not
     an engineering one
      budget 2^214.9 ops   ->   REACH  n = 31  (LOW model)   n = 30  (KR model)

E.  CALIBRATION -- does the model reproduce the literature's ACTUAL frontier?
------------------------------------------------------------------------------
The conjecture is verified to n = 14 (mg-33f5, preprint; n = 12 refereed).
That number was produced by a real computation with real cleverness, and it is
the only external check this model has.  If the model said n = 30 was easy or
n = 8 was hard it would be worthless.

    n=12   work 2^40.4 ops  =    4.58e-05 core-years at 1e9 ops/s
    n=13   work 2^45.8 ops  =    0.001938 core-years at 1e9 ops/s

    n=15   work 2^58.0 ops  =       9.138 core-years at 1e9 ops/s
    n=16   work 2^64.8 ops  =        1016 core-years at 1e9 ops/s

=> the model puts the single-machine frontier at n = 14-16 and the
   cluster frontier a couple of elements above.  THE LITERATURE IS AT
   n = 14.  The model is calibrated, and if anything optimistic.

------------------------------------------------------------------------------
F.  THE EXCHANGE RATE -- what a future structural result would be worth
------------------------------------------------------------------------------
A pruning of b bits buys Dn = b / g(n) extra elements, g(n) = log2(N(n)/N(n-1)).
This is the number that decides whether any structural theorem is worth proving
FOR SEARCH PURPOSES.  It is not a statement about mathematical value.

     n |   g(n) | bits to buy +1 | bits to buy +5 | a 99.9%-discarding
       |        |     element    |    elements    | constraint buys
------------------------------------------------------------------------------
    14 |   5.31 |            5.3 |           26.5 | +1.88 elements
    16 |   6.04 |            6.0 |           30.2 | +1.66 elements
    20 |   7.50 |            7.5 |           37.5 | +1.33 elements
    25 |   9.32 |            9.3 |           46.6 | +1.07 elements
    34 |  12.61 |           12.6 |           63.0 | +0.79 elements
    50 |  18.45 |           18.4 |           92.2 | +0.54 elements
    98 |  35.97 |           36.0 |          179.8 | +0.28 elements

MEASURED, for comparison: all four literature constraints together prune
0.07 bits at n = 20 and 0.00 bits at n = 36.  At n = 20 that is +0.01
elements of reach.  Not one element.  One hundredth of one.

------------------------------------------------------------------------------
G.  THE INVERSE QUESTION: what would a constraint have to DO?
------------------------------------------------------------------------------
For each illustrative target, the pruning a future structural result would
have to supply to bring it inside the largest budget above (2^214.9 ops).

  target n | log2 WORK (LOW) | pruning REQUIRED | as a surviving fraction
------------------------------------------------------------------------------
        20 |            94.9 |             none | inside the PHYSICAL limit, not any machine
        25 |           140.5 |             none | inside the PHYSICAL limit, not any machine
        34 |           245.4 |          30.5 bits | 1 in 2^30
        50 |           504.6 |         289.7 bits | 1 in 2^290
        98 |          1842.2 |        1627.3 bits | 1 in 2^1627
       398 |         29251.0 |       29036.1 bits | 1 in 2^29036

READING.  A constraint delivering hundreds of bits is not a constraint, it is
a classification: it would have to collapse the population from 2^(n^2/4) to
something sub-quadratic in the exponent.  No shape constraint of the kind
mg-5998 records -- rigid, width >= 3, an element incomparable to >= 7 others --
can do that, because each of them is an ALMOST-SURE property of a random poset
(Kleitman-Rothschild) and an almost-sure property prunes o(1) bits by
definition.  That is not a limitation of these three; it is a limitation of the
whole category.
