==============================================================================
J2e  THE GENERAL FORM, ON J2
==============================================================================

  J2 decides whether other scripts' statuses were discarded, so the
  question is whether J2 discards its own.  Checked, with the reason:

   1. Every execution here is `L.run_sh`, which is
      `subprocess.run(["/bin/sh", <name>], ...)` -- a LIST argv, no
      `shell=True`, therefore no shell, therefore no pipeline.  That is
      the branch that CANNOT exhibit the defect and the reason is
      structural rather than a promise about how it is called.
   2. `returncode` is read on every path.  The timeout path returns
      None and prints as `-`, never as 0 -- a timeout rendered as 0
      would be this defect in a different costume.
   3. J2c's verdict is a CONJUNCTION: the exit code AND whether the
      forced text reached the runner's stdout.  Scoring the code alone
      would not distinguish `the stub ran and was caught` from `the
      stub never ran`.
   4. J2c snapshots `git status --porcelain` before and after, because
      it writes over three tracked self-tests and a restore that did
      not happen would silently corrupt every later section.
   5. J2a is run at BOTH revisions, and the pin is the finding: a scan
      pinned to one revision is reported as of that revision and not
      as of the repository.
   6. WHAT J2 CANNOT DO, said here rather than omitted: it finds
      consumers by a syntactic rule over `.py` and `.sh`.  A consumer
      that reaches a runner through a path assembled at runtime from
      data is invisible to it, exactly as it was to the sweep's K2a.
      J2a's rule is strictly wider than K2a's -- it resolves helper
      functions and list-valued tree names -- but wider is not total.
