§1  THE WATCHED CLASS
--------------------------------------------------------------------------------------------
  every tracked file under code/ named out_*.txt, compared against HEAD.
  Nothing is regenerated by this arm; it only reads.  A transcript no suite
  rewrites is never modified and therefore never appears in the changed set —
  which is how mg-c824's out_a4_census.txt stays outside this control by
  construction rather than by exemption.

  NOTHING IS EXEMPT.  THE CLASS IS TOTAL, AND THIS ARM'S OWN TRANSCRIPT IS IN IT.
  It was the one exclusion until mg-c15e, because its text named the disagreement
  set and that set is emptied by the very commit that carries the file — so each
  run's fix was the next run's disagreement, 16 of 31 committed versions RED and 7
  commits of main existing for nothing else.  The exclusion is gone rather than
  narrowed: §2 no longer records the outcome, so there is nothing left to oscillate
  and no file that needs forgiving.  Worlds E1-E8 in g1 hold the class to that.

  HOW MANY MOVED, WHICH WERE GRADED NOISE, AND WHAT DISAGREED ARE ON STDERR AND NOT
  HERE.  That set is not a fixed point of this arm's own commit, and an earlier
  draft that printed it made THIS ARM fail its own invariant on its second run.
  The build log keeps stderr and no tracked file does.  README D4.

  AND 1 TRANSCRIPT(S) ARE GRADED AGAINST A CORPUS PIN RATHER THAN AGAINST THIS
  TREE, because their subject IS the tree and so they have no per-branch fixed
  point.  The list is declared, not a shape a transcript can grow into:
      code/control_audit_9876/out_a4_sweep.txt
  A pin that moved says the corpus moved and the difference is not this branch's.
  The SAME pin beside a moved text says the instrument changed its answer on an
  unchanged corpus, and is RED.  Drift past 10 directories is STALE, also red.
  HOW FAR EACH HAS DRIFTED IS ON STDERR, for the reason the paragraph above gives:
  it moves with every landing and this file must not.  lib_f771.CORPUS_SCOPED.

§2  THE INPUTS THE VERDICT IS A FUNCTION OF — AND NOT WHAT IT CAME OUT AS
--------------------------------------------------------------------------------------------
  THIS SECTION REPLACED THE DISAGREEMENT SET, AND THE REASON IS NOT TASTE.
  This arm's transcript is committed by the same act that REPAIRS what it
  reported — the repair is `commit the regenerated transcripts` — and that
  act sets the disagreement set to empty.  A transcript naming that set is
  therefore false about the tree it lands in BECAUSE it landed there, and no
  exemption is needed for a file that does not try to record one.  What is
  below is invariant under the repair; the outcome of this run is in the EXIT
  STATUS and on stderr, which is what the merge gate has always read.

  THE RULES THAT ARE SPELLED AS CONSTANTS, IN FULL AND NEVER TRUNCATED:
    ROOT_MARK                "<ROOT>"
    FS_ROOTS                 r"(?:Users|home|var|private|tmp|opt|mnt|srv|data|workspace)"
    ABS_TO_REPO              re.compile( r"/" + FS_ROOTS + r"/[^\s:'\"]*?(?=/(?:code/|docs/|
                             STATE\.md|build\.sh))")
    ABS_ANY                  re.compile(r"/" + FS_ROOTS + r"/[^\s:'\"]*")
    SECONDS                  re.compile(r"\b\d+\.\d+\s*s\b")
    CORPUS_PIN               re.compile(r"^corpus pin: ([0-9a-f]{12})\s+\((\d+) directories"
                             , re.M)
    PRODUCER_PIN             re.compile(r"^producer pin: ([0-9a-f]{12})", re.M)
    CORPUS_DRIFT_LIMIT       10
    RED_VERDICTS             ("DISAGREES", "STALE")

    sha256  6617f6577473ec6ca0be028d3d82ac358cbb690336417fa15184065ba1f5725b
