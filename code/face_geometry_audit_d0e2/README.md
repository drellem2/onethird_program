# `face_geometry_audit_d0e2` — independent audit of mg-5f9a (`5cae82c`)

Regenerates every number quoted in `docs/audit-mg-5f9a-deletion-test.md`.

```sh
./run_all.sh        # 26 s, 25 claims, 0 BROKEN, 3 findings, exit 0
```

| file | what it measures |
|---|---|
| `kernd0e2.py` | the mutation machinery: copy `../face_geometry` to a temp dir, apply anchored source edits, run `controls.py` as a subprocess, return stdout **as bytes** |
| `e1_deletion.py` | **the deletion test**, on all four gates `ABSORB_GATES` names plus five more; predictions registered before every run |
| `e2_parity.py` | why one deletion moved nothing: where the predicate returns, per named population, over 857 pairs |
| `e3_seams.py` | the seams of a twice-corrected artifact; the repair's own "0 label change(s)" check, run on an artifact where every row reads `[FAIL]` |

**Why not just run `../face_geometry_instr_5f9a/d2_deletion.py`.** That is the subject's own
instrument and it reports the subject passing. An audit that runs it learns only that it is
deterministic. So the mutations here are re-derived from the source text of `absorb_trace`, the
baseline is generated by this directory, and the mutation set is a superset — mg-5f9a ran the
deletion on two of the four gate labels its own `ABSORB_GATES` tuple defines.

**Nothing under `../face_geometry` is written.** Every mutation goes to a copy in a temporary
directory; every battery run captures stdout instead of tee-ing it.

**Anchors must match exactly once.** A source edit that matches twice, or not at all, is a silently
different experiment — the failure mode that lets a deletion test report on a deletion it never
made. `apply_edits` raises instead. (It caught a real bug while this was being written: an
`open(path, "w")` that truncated the file before the read expression was evaluated, which would
otherwise have run nine "deletion tests" on unmutated source.)

**Exit status is about this audit, not about its subject.** `[FINDING]` = a defect in mg-5f9a, does
not fail the script. `[BROKEN]` = a claim of this audit's own that did not hold, and does. An audit
that exits 1 whenever it finds something cannot be re-run by the person fixing it.

**No `| tee`.** A pipeline's exit status in POSIX sh is the last command's, so `tee` would mask a
verifier exiting 1 — a committed transcript reading BROKEN under a `run_all.sh` that exited 0.
mg-f922 found that shape in this repository.
