s1.1  LL_n <-> POSETS IS A BIJECTION — so the consumable half is a function of P
==============================================================================
  [GREEN] n = 2: |LL_n| = 3 distinct extension sets from 3 posets   A001035 says 3 — INJECTIVE, no collisions
  [GREEN] n = 3: |LL_n| = 19 distinct extension sets from 19 posets   A001035 says 19 — INJECTIVE, no collisions
  [GREEN] n = 4: |LL_n| = 219 distinct extension sets from 219 posets   A001035 says 219 — INJECTIVE, no collisions
  [GREEN] n = 5: |LL_n| = 4231 distinct extension sets from 4231 posets   A001035 says 4231 — INJECTIVE, no collisions
       Surjective by definition and injective by the count, with `s0.3` supplying the inverse
       explicitly (`P = intersection of L(P)`).  So:
       
         THE CONSUMABLE RESTRICTION OF ANY SUBSET-CONSTRUCTION IS A FUNCTION OF THE POSET.
       
       This is mg-8b32's C1 arriving by a different road.  C1 says a function of `P` factors
       through `pi` because `P = {(x,y) : pi_xy = 1}`.  The road here does not mention `pi` at
       all: it says that the SET `L(P)` already determines `P`, so a construction that reads
       the set reads nothing the poset did not already carry — AT THE INPUTS WHERE IT CAN BE
       CONSUMED.  Daniel's class survives C1 exactly because `S` ranges wider than `LL_n`, and
       s1.2 measures how much wider, and s1.5 measures what the extra width is worth.

s1.5  WHAT EACH IS WORTH AS A BOUND, IN BITS — the sharpest bound each can support
==============================================================================
       For a construction Phi the SHARPEST bound derivable from it is
           B_Phi(v) = max{ e(P) : Phi(L(P)) = v },     and then   e(P) <= B_Phi(Phi(L(P))).
       Nothing weaker is a bound and nothing stronger is derivable, so this is the whole
       consumable content of Phi.  The free bound is e(P) <= n!; the gain is what B_Phi saves
       against it, in bits, and ZERO gain is the definition of unconsumable.
       
       THE POPULATION IS THE ONE THE SEPARATOR IS DEFINED ON, AND THAT MATTERS — T2a and T2c
       read `L*`, which does not exist at every poset (s1.4's `defined on` column: 2040 of 4231
       at n = 5).  The free bound is therefore taken as `max e(P)` over THAT population, not
       over all posets.  Bucketing `undefined` as if it were a value is what the first draft of
       this section did, and it credited T2a with 2.26 bits it has not got: the split it was
       scoring is `does L* exist`, which is a TIER-0 function of `pi` and not the row.

s1.6  AND THE SURVIVOR'S BOUND IS CIRCULAR — the second failure mode, measured
==============================================================================
       A bound is consumable only if its right-hand side is CHEAPER TO KNOW than e(P).  The BK
       edge count on L(P) is a sum over L(P), so knowing it presupposes the enumeration that
       gives e(P) outright.  That is the `gap(mu)` defect again.
       
       AND THE RUN MADE THAT THE *ONLY* REASON, WHICH THE FIRST DRAFT OF THIS SECTION GOT
       BACKWARDS.  It asserted that |E| fails to determine e(P) and the measurement says the
       opposite — printed as measured, because a stronger survivor makes the verdict rest on
       cost alone rather than on two half-arguments:
  [GREEN] n = 3: |E| takes 4 values over 19 posets   0 of the 4 are ambiguous about e(P)
  [GREEN] n = 4: |E| takes 10 values over 219 posets   0 of the 10 are ambiguous about e(P)
  [GREEN] n = 5: |E| takes 29 values over 4231 posets   1 of the 29 are ambiguous about e(P)
       |E| = 4    ->  e(P) in [4, 5]
       
       SO AT n = 3, 4 THE EDGE COUNT DETERMINES e(P) OUTRIGHT and the ambiguity only appears at
       n = 5.  A `res > 1` construction that is very nearly an e(P)-oracle is exactly what a
       consumability hunt would want — and it is unconsumable anyway, for the reason above.
  [GREEN] and e(P) - 1 <= |E| at every poset, n = 3   BK-graph connectivity — |E| is bounded BELOW by e(P), never above it
  [GREEN] and e(P) - 1 <= |E| at every poset, n = 4   BK-graph connectivity — |E| is bounded BELOW by e(P), never above it
  [GREEN] and e(P) - 1 <= |E| at every poset, n = 5   BK-graph connectivity — |E| is bounded BELOW by e(P), never above it
       SO THE INEQUALITY RUNS THE WRONG WAY FOR THE PROGRAMME.  `e(P) <= |E| + 1` is true and
       useless: it bounds the thing we cannot compute by a strictly larger thing we can compute
       only by computing it.  The s1.5 gain is real, and it is not consumable — which is why
       this arm reports TWO failure modes and not one.
