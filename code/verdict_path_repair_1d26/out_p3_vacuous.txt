P3c  THE DEAD MAN'S SWITCH
==============================================================================

  `sys.exit(1 if bad else 0)` as the last line of a checker is a line
  whose DELETION exits 0: CPython gives status 0 to a process that runs
  off the end of its own module, so losing the verdict WAS a pass.  The
  switch is armed at the top of the checker and fires at interpreter
  shutdown if nothing was ever delivered.

      armed, and a verdict delivered (clean)         exit 0    expected 0    ok
      armed, and a verdict delivered (red)           exit 1    expected 1    ok
      armed, and abandoned                           exit 9    expected 9    ok
      armed, and abandoned after a sys.exit(0)       exit 9    expected 9    ok
      NOT armed, and abandoned -- must stay 0        exit 0    expected 0    ok
      delivered with `sys.exit` neutralised -- the switch carries the code exit 1    expected 1    ok
      the same, with nothing wrong to report -- must be 0 and not 9 exit 0    expected 0    ok

  7 of 7 switch cases return the exit code they must               ok
        The fourth is the one that matters most: a deletion that leaves a
        `sys.exit(0)` reachable ahead of the verdict is still caught.
        The fifth is the row that must say NO -- `e1_extents.py`,
        `e3_bothways.py` and `selftestd633.py` import this kernel and do not
        deliver through it, and arming them would redden three runs that are
        not lying about anything.
