  DECIDED: 6,000 WORDS IS NOT THE THRESHOLD THIS RATCHET GETS SET TO, and the
  reason is not that the target was wrong when mg-ea0e chose it.  It is that a
  gate set to 6,000 today is RED ON ARRIVAL — 13077 words over — and would block
  every merge in this repository from the moment it landed, for a reason no
  author of an unrelated branch can act on.  gate.py's own docstring refuses
  exactly that construction, in those words, about a different suite.

  A ratchet is not a target.  It is a MONOTONE FLOOR UNDER A REGRESSION: it
  says the file does not get bigger than it is now without somebody saying so
  in writing.  Set it where the file stands and it binds from today; set it at
  an aspiration nobody has met and it is either removed within a week or
  suppressed, and a suppressed control is worse than none (mg-d91f).

  THE 6,000-WORD TARGET IS NOT WITHDRAWN AND IT IS NOT MINE TO WITHDRAW.  It
  remains what mg-ea0e aimed at and what `docs/state-history/` was built to
  make reachable.  The gap is 13077 words and it is a DEBT with a named remedy
  (relocate attempt rows to their per-attempt files), not a number to assert
  into a config file and call enforced.  Every landing that pays some of it
  down must lower the ceiling in the same commit — which is what the
  SLACK-UNRATCHETED half of the rule exists to force, and it is the half that
  makes this a ratchet rather than a cap.
