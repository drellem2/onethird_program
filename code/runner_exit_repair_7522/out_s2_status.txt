==============================================================================
S2e  THE GENERAL FORM, ON THIS SECTION
==============================================================================

  S2 is a script that decides whether other scripts' statuses were
  discarded, so the question it owes is whether it discards its own.
  Enumerated, with the branches that CANNOT exhibit it and why:

   1. Every subprocess here is a LIST argv with no `shell=True`, so no
      shell parses it, so there is no pipeline, so `returncode` is the
      target's own status.  Structural, not a promise about callers.
   2. `returncode` is read on EVERY path including the timeout path,
      which returns None and prints `-`, never 0.
   3. Both arms are written to a scratch file and run from there, so
      neither edits a tracked runner -- which is what makes S2d's
      worktree comparison mean anything.
   4. Every control verdict is a CONJUNCTION of exit code AND reach.
      Reach is stamped-mtime, read BEFORE any restore.
   5. The forced failure writes its marker to STDERR, so it cannot
      land in the transcript whose bytes S2d checks.
   6. The transcripts are restored by writing back exact bytes, not by
      `git checkout -- .`, which rewrites every tracked file and would
      have destroyed the mtime evidence in 4.
   7. The LIMIT, stated: S2 forces these targets to FAIL, so it does
      not re-prove that they pass.  S2a is the row that shows they do,
      at HEAD, on this machine.
