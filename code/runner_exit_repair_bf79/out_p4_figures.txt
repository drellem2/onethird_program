==============================================================================
P4e  AND A CLAIM `figures()` MAKES THAT IT DOES NOT KEEP
==============================================================================

  Found by this repair rather than looked for, which is why it is here
  and not in the brief.  mg-70c7's `figures()` carried this comment
  above it, deleted with the body it described:

      # Numbers that are not figures: a section number, a year, a line
      # reference of the form `file.py:214`, a git revision.

  A GIT REVISION IS NOT EXCLUDED AND NEVER WAS.  A short revision that
  happens to be all decimal digits is matched by `_NUMBER` and passes
  every exclusion.  This is not hypothetical: repairing O1 required
  naming a revision in mg-70c7's README, and `r6_self.py`'s E2 promptly
  reported it as a FIGURE NO TRANSCRIPT BACKS.  The check was right by
  its own rule and the rule's stated exclusion list was false.

      `3738079 `  all digits: yes  read as a FIGURE: yes  resolves: yes
      `973ca61 `  all digits: no   read as a FIGURE: no   resolves: yes
      `1234567 `  all digits: yes  read as a FIGURE: yes  resolves: no
      `9715841 `  all digits: yes  read as a FIGURE: yes  resolves: no

      IS THIS REPAIRED HERE?  NO -- and the reason is measured, not an
      excuse.  Both candidate rules are wrong:
          DISTINCT FIGURES in every committed transcript  1291
          ...FIGURES of magnitude >= 1e6                   34
          ...FIGURES resolvable as a git object             7

      A MAGNITUDE rule (`drop >= 1e6`) would drop 27 genuine figures,
      among them `2147483647`, which is INT_MAX in a fixture and a real
      measurement.  A RESOLVES-AS-AN-OBJECT rule would drop 7, and it
      would drop them for a reason that is an accident of this
      repository's object database rather than a property of the number.
      Neither is right, so the finding is REPORTED AND NOT FIXED, and
      the prose this ticket writes names revisions in a form that is not
      all digits or does not name them at all.  A generous exclusion
      list turns an unbacked figure into a non-figure -- `lib70c7`'s own
      sentence, which is why the wrong fix is worse than the finding.
