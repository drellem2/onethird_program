  The ledger this repair asks of its subject, asked of itself, with the
  same instrument: `lib56dc.count_rows` for the population and
  `lib56dc.grain_of` for the grain and the STAGE.  The bar is higher
  here than the one `r6_self.py`'s E1 sets -- E1 accepts a grain word
  anywhere in a two-line window, and this requires stage `label`.

  WHY HIGHER, since a self-imposed harder test is the shape mg-dee4's F3
  is about in reverse: `mg-03d1` reads LABELS, so a grain word of mine
  that is only reachable from a header is a count my auditor will
  classify by looking two lines up -- and if it looks two lines up it is
  reading a row that is not mine to control.  Putting the word on the
  label is the only version of this I can guarantee.

  AND THE ONE ARTIFACT THIS CHECK COULD NOT SEE, closed rather than
  noted.  `run_all.sh` truncates each transcript with `>` BEFORE its
  probe runs, so when this probe runs, `out_p5_self.txt` is EMPTY -- and
  the strictest rule of this tree therefore excluded exactly one
  artifact: ITS OWN OUTPUT.  That is O2's shape -- a population that
  excludes the thing it is about -- found in the repair of O2, and found
  only because the probe was once run OUTSIDE its runner, where the
  truncation does not happen.  It had NINE offending rows.

  THE FIX IS IN THE RUNNER AND IT IS STRUCTURAL.  `run_all.sh` now writes
  each probe's output to `<transcript>.new` and MOVES it, so the previous
  run's bytes survive for the duration of the probe and this check reaches
  its own output like any other.  Reading the COMMITTED copy instead was
  the first fix and it does not converge: the committed transcript is
  itself the thing being checked, so a stale one keeps reporting its own
  staleness forever.  That fallback is KEPT for the genuinely-absent case
  -- a first ever run, before any transcript exists -- and the source of
  every row is printed so a reader can see which is which.
