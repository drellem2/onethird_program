K2d  THE RUNNER WITHOUT `set -e` -- a different defect, named separately
==============================================================================

  code/species_audit_7dd3/run_all.sh is the one affected runner with NO `set -e`.
  Its own header says:
      # that is what this audit found.  The self-test is the only file whose exit
      # code is a statement about this instrument rather than about the repair.

  So its self-test's status IS meant to be load-bearing.  It was not,
  and `| tee` is only half the reason: with no `set -e` and every other
  step ending in `|| true`, the last command of the script is an
  `echo`, so THE RUNNER EXITED 0 UNCONDITIONALLY -- with or without the
  pipeline.  Removing the pipeline alone would not have fixed it.
  The repair is therefore an explicit `|| { ...; exit 1; }` guard on
  the self-test, which is what makes the header true; the `|| true` on
  d1..d6 is deliberate and is left exactly as it was.

  on disk now: guard present = True

==============================================================================
K2e  THE FIX, AND WHY THIS MECHANISM
==============================================================================

  MECHANISM USED: redirect the script to its transcript, read the
  status with an explicit `||` guard, then `cat` the transcript.

      python3 x.py > out_x.txt || {
          cat out_x.txt; echo "x.py FAILED"; exit 1; }
      cat out_x.txt

  WHY NOT `set -o pipefail`.  The shebang is `#!/bin/sh` on 59 of the 64
  runners -- measured, not assumed.  On Linux that is normally dash,
  which has no `pipefail`:
  `set -o pipefail` there writes "Illegal option -o pipefail" and
  returns non-zero, and under `set -e` that aborts the runner at the
  line that was supposed to make it safer.  It would work on macOS,
  where /bin/sh is bash in POSIX mode, and fail on the other half of
  the world -- the worst possible split for a control.

  WHY NOT `${PIPESTATUS[0]}`.  Bash-only, for the same reason, and it
  needs a separate `if` after every pipeline anyway -- more source than
  the redirect form, with a portability cliff attached.

  WHY THIS ONE.  It is POSIX; it is what mg-e1d0 and mg-821e already
  used in this repository, so the arc now has ONE idiom instead of
  three; and it writes the transcript with the same bytes `tee` wrote,
  so no committed out_*.txt changes and no byte-comparison anywhere in
  the arc is disturbed.  K3 checks that claim rather than asserting it.

  WHAT IT COSTS, stated because it is a real regression: `tee` streams,
  a redirect does not.  On the two long runners (branching_audit_2060,
  ~20 min; species_audit_7dd3, ~3 min) the transcript now appears at
  the end of each step instead of live.  Correctness over progress
  bars; the alternative that keeps streaming is `pipefail`, and it is
  not available here.

==============================================================================
K2f  THE GENERAL FORM, ON THIS INSTRUMENT
==============================================================================

  This file consumes exit statuses too: `can_fail()` shells out to
  `git show` through `L.read`, and K2a shells out to `git ls-tree`.
  Enumerated, with the reason each cannot exhibit the defect:

   1. L.read/L.runners use subprocess.run(..., check=True) with NO
      shell and NO pipe -- there is no last-command status to inherit.
      A failing `git show` raises CalledProcessError, which is caught
      exactly once, at can_fail(), and returns the verdict `None` that
      K2b prints as `-` rather than silently as `no`.
   2. The `git ls-tree` in K2a is NOT check=True, deliberately: its
      output is then USED, so a failure shows up as an empty caller
      table rather than as a pass.  An empty table would be visible
      here in a way an unread status would not.
   3. This script has no pipeline of its own and is invoked by
      run_all.sh through a redirect and an explicit guard, not a pipe.
      selftestc2b3.py section H measures that on the runner's bytes.

  AND WHAT IS NOT MECHANICAL, said plainly.  Two rows of K2a's table
  are HAND-ADDED, because a line-local scan cannot resolve either:
    * b0_repro.sh:10 runs `./run_all.sh` in a directory whose identity
      comes from a `cp -R` two lines earlier;
    * p3_wiring.py:214 runs `run_runner(t)`, where `t` is a loop
      variable over three tree names.
  Both were read by hand and both are in the AFFECTED column.  A table
  that silently dropped them would have reported one caller instead of
  three and made this ticket look smaller than it is.
